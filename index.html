01

2026 — Concurrency & Systems

LedgerLock

An idempotent transaction manager that stays correct under retries. Duplicate requests sharing an idempotency key return the original result instead of double-charging, enforced by a unique DB constraint; row-level locking under READ COMMITTED isolation stops lost updates when concurrent requests hit the same account. Verified with a concurrency test harness: 100 simultaneous duplicate requests processed exactly once, 50 concurrent distinct-key requests produced zero lost balance updates.

2026 — Razorpay Buildathon

RENEW

A deterministic recovery-operations ledger for failed recurring payments — diagnose → score → decide → audit. A logistic-regression scorer flags recoverable segments; every actual decision runs through unit-tested deterministic rules, not the LLM, which I deliberately scoped to drafting outreach copy only. Found a batch that looked profitable in aggregate but was break-even on one structurally unrecoverable segment, and fixed it with a recoverability-threshold rule.
